# 서린 안내자와 charchat 제작 연결 — 0.3.3

2026-11-22. 사용자가 캐릭터 스튜디오의 **서린**을 지정했다. 초기 로봇 제안은 폐기했고 실제 로봇 이미지는 생성하지 않았다. 기존 서린을 게임 마스코트·초기 안내자로 사용한다.

## 제작 원본과 에셋

charchat 관리자 계정(id 1)에 고정된 제작 전용 인증으로 새 MCP 도구를 호출했다. 기존 스튜디오 actor **1: 서린**의 기본·SF 사진을 확인하고, 은발·옆 땋은 머리·보라색 눈·눈 아래 점을 유지하는 외형/LoRA 자료를 재사용했다. 배우 자료 자체나 다른 회원 작품은 수정하지 않았다. charchat의 별도 제작 brief **1**에 설정·이미지 이력·선택 결과를 남겼다.

첫 Wai concept(asset 1, seed 142731)은 머리 길이가 달라지고 글자가 들어가 제외했다. Animagine 모델과 해당 배우의 기존 LoRA(`charchat_actor1_animagine_20261118093522.safetensors`, 강도0.7), seed **734921**로 대화용 이미지 네 장을 생성했다. 기본 원화로 asset **2**를 선택했다. 총 실제 생성 요청은 **5장**, 신규 LoRA 학습은 0회다. 이미지를 더 이상 생성하지 않고 기존 작업 상태만 조회했다.

이미지는 charchat → Nightshift 관리자 소유 생성 경로를 통해 만들었다. 다른 이미지 생성 서비스를 사용하지 않았다. 원본은 charchat에 보관하고 게임에는 768×768 WebP(각 약79~85KB)를 내보냈다. 원본·내보낸 파일 해시는 `public/mascot/manifest.json`에 기록했다. 형식/크기만 변환했으며 다른 캐릭터로 덧그리지 않았다. 꽃 장식·옷깃·명암 등 세부에는 차이가 남아 있고, 모든 그림을 같은 복장/조명의 완벽한 리깅 스프라이트로 간주하지 않는다. 추후 배경·의상 고정과 추가 표정 보강이 가능하다.

관리자 이미지 워커 기동은 사용자에게 비용 발생을 설명한 뒤 명시적으로 승인받았다. 관리자 소유 이미지 워커 한 개를 켜고 제작 완료 후 작업 중 종료를 차단하는 기존 Nightshift MCP 경로로 껐다. `enabled=false`, URL 없음까지 확인했다. 다른 워커와 Nightshift 설정은 변경하지 않았다.

## 게임 대화창

`src/game/guide/GuideDialogue.tsx`는 도시의 비모달 안내창이다. 초기에는 다섯 단계 안내(카메라 → 거점 내부 → 확보/복구 → 자원/인력 → 외교)를 보여준다. 다음·건너뛰기·접기·다시 열기·처음 안내 재시작을 지원한다. ‘현재 상황/자원/주민/남작 조건’을 선택하면 실제 상태에 맞는 설명을 보여준다. 운영실·거점 내부 버튼은 기존 화면 전환만 호출한다.

`guide.ts`는 GameState와 기존 Presentation Adapter를 읽는 순수 함수다. 부족 여부는 실제 원장의 unmet, 주민 수/부상은 실제 생존 Person, 복구는 실제 건물 상태, 남작 조건은 기존 `titleRequirements()`를 사용한다. 계승 대기와 게임 종료도 구분한다. 자원·배정·전투·계약·계승 결정을 실행하거나 별도 시뮬레이션 타이머를 만들지 않는다. 자유 입력 LLM 채팅은 이번 범위에 없다.

도시의 기존 큰 오버레이가 열리면 안내창을 숨기며 오버레이 내부 포커스/입력과 경쟁하지 않는다. 열었던 상태와 진행은 그대로 유지한다. 키보드로 직접 열었을 때 포커스를 안내창으로 옮기고 접으면 호출 버튼으로 돌려준다. 첫 자동 안내는 카메라의 포커스를 빼앗지 않는다. 이미지 로딩 실패 시 실패 안내를 표시하며 가짜 원화를 그리지 않는다.

## 저장과 호환

게임 저장 스키마는 **2** 그대로다. 안내 진행/접힘 상태는 별도 localStorage **`ashen-city-guide-v1`**에 캠페인 ID와 함께 저장한다. 손상된 UI 데이터·차단된 localStorage는 게임 시작을 막지 않는다. 기존 게임 슬롯을 읽거나 덮어쓰지 않는다. 새 캠페인은 초기 안내부터 시작한다. JSON 게임 내보내기에 안내 진행은 포함하지 않는다. 브라우저 자체 데이터를 지우면 안내가 다시 표시될 수 있다.

## 검증

- charchat 제작 도구: 가짜 공급자로 전용 인증·계정 정지·소유권·기존 스튜디오 actor 접근·실제 LoRA payload·미가동 워커 미접수·중복 request ID·한도 기록·접수 불명확 미재시도·이미지 조회·선택·설정 수정 검사 통과. 운영 DB 사본 추가 마이그레이션에서 기존 주요 행 수 보존 확인.
- 실제 stdio MCP 연결로 도구 목록·capabilities·기존 서린 사진·설정 생성/수정·생성·선택을 호출했다. 이후 동일한 제작 API로 완료 상태와 이미지 다운로드를 확인했다. 생성된 이미지 파일은 직접 열어 확인했다.
- city의 새 안내 테스트 **3개 통과**: 원장/주민/작위/계승과 상태 불변, 안내 진행/접기/복원, 오버레이 숨김/손상 UI 저장. 셸 회귀 **7개 통과**. 새 테스트의 Node26/jsdom localStorage 미제공 문제는 메모리 저장소 fixture로 보완했다. 실제 브라우저에서 저장 접근 실패도 예외 처리한다.
- `npm ci`, TypeScript 검사, 프로덕션 `.release-stage` 빌드 통과. 정적 WebP 파일의 원본/스테이지 해시 일치 확인. 기존 도시 번들의 500KB 경고는 남아 있다. 경제 엔진을 바꾸지 않아 관련 없는 전체 검사는 반복하지 않았다.
- 최신 작업 선호에 따라 브라우저 실행·화면 캡처·성능 재측정은 하지 않았다. 수동 확인: 도시에서 서린 안내 → 다음/건너뛰기 → 상황별 질문 → 운영실/거점 → 도시 복귀 → 접기/새로고침 후 재열기. 모바일에서 안내창과 도시 조작 버튼의 겹침도 확인할 항목이다.

## 변경 파일과 후속 작업

`src/game/guide/{guide.ts,GuideDialogue.tsx,guide.css}`, `src/game/GameShell.tsx`, `tests/guide.test.tsx`, `public/mascot/*`, WebP 응답 형식을 추가한 `server.mjs`, 버전 표시 `src/App.tsx`·`package.json`·`package-lock.json`, README와 이 기록을 변경했다. 기존 카메라·경제·저장·전투 모듈은 변경하지 않았다.

charchat 도구 연결 상세는 해당 저장소의 `docs/CREATIVE_AGENT.md`에 있다. Codex 로컬 MCP 이름은 **charchat**이며 새 세션/도구 재연결에서 사용한다. 현재 연결 방식은 같은 PC의 stdio 브리지다. 외부 기기의 원격 MCP 연결이나 별도 웹 갤러리 UI까지 구현한 것은 아니다.
