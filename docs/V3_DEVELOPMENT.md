# ASHEN CITY v3 개발 기록

기준 커밋 `fedb4ef`의 v2 게임 엔진·저장 포맷을 유지한다. 작업 브랜치는 `feature/v3-spatial-world`. 운영 v2의 `dist/`는 최종 검증 전 교체하지 않는다.

## 아키텍처와 변경 계획

- 기존 `App.tsx`의 단일 상태·시간·저장 소유권을 유지하고 `game/GameShell.tsx`로 공간 화면과 관리 화면을 전환한다.
- `game/presentation/GamePresentation.ts`는 `economy()`와 기존 상태를 읽어 도시·방·주민의 표시 상태를 계산한다. 렌더러는 자원·생산·전투를 쓰지 않는다.
- 도시: Three.js + R3F + Drei, `game/city/`. 직접 제작한 절차적 건축·도로·잔해·식생과 카메라를 구현한다.
- 내부: PixiJS, `game/building/`. 대표 쉘터 5개 층, 고정 방 ID와 경로 그래프, 인체 리깅·작업 애니메이션을 구현한다.
- 관리: `management/ManagementView.tsx`가 기존 대시보드를 그대로 감싼다. 선택 건물은 공유한다.
- HUD와 성능 측정·정리 코드는 별도 모듈로 둔다. 층/방/주민 위치·걷기 프레임·카메라는 저장에 넣지 않는다.

## 호환성 위험과 제한

저장 버전은 v2 그대로다. 최초 화면만 도시로 바뀌며 기존 슬롯·원본 백업·부재 계산 경로는 유지한다. 계승/종료 대기에는 관리 화면으로 안내하고 자동 결정하지 않는다. GPU 실패 시 관리 화면으로 접근할 수 있어야 한다.

쉘터의 여러 생산 방은 기존 기초 생산의 시각적 위치다. 새 시설이나 층별 생산을 추가하지 않는다. 다른 건물은 건물당 시설 1개를 유지한 축소 내부도로 제공한다. 미복구/미가동 공간은 명시하고 연구·의료 생산을 꾸미지 않는다. 외근 주민을 쉘터에서 일하는 장식으로 표시하지 않는다.

## 단계 상태

- Phase A: 공유 상태·화면·투영 기반 완료. 기존 41개 포함 테스트 48개, 타입 검사·빌드 통과. 이 단계의 공간 화면은 명시적 연결용 임시 화면이며 최종 그래픽이 아니다.
- Phase B: 3D 도시 대기.
- Phase C: PixiJS 내부 대기.
- Phase D: 주민 경로·애니메이션 대기.
- Phase E: 전체 상태 동기화 검증 대기.
- Phase F: 그래픽·조작·성능 실측 대기.

브라우저 검증과 실제 프레임 수치는 수행 후 기록한다. 전체 화면·전체 사이트 캡처는 하지 않는다.

Phase B 검증: 유형별 절차적 메시·20동·도로·식생·그림자·카메라·선택·실제 명령·WebGL 대체 경로 구현. 테스트 52개와 타입/빌드 통과. 로컬 실제 브라우저 도시 렌더링 약 57 FPS 관찰. 최종 품질/수명주기 측정은 Phase F에서 진행한다.

Phase C 검증: PixiJS 5층 단면·계단·10종 공간 설비·방 선택·층 집중·줌/이동/전체 보기 구현. 실제 브라우저에서 설비와 방 목록을 확인했다. 관련 테스트 11개와 타입/빌드 통과. 주민은 다음 단계에서 연결한다.

Phase D: 기존 Person ID별 인체 리깅·역할별 작업·부상/휴식·경계/운반 이동·계단 BFS 경로를 연결했다. 이동/작업 변경/부상 속도/일시정지 순수 테스트 4개를 추가했고 관련 15개 테스트와 타입/빌드가 통과했다. 브라우저에서 실제 작업 재배치와 정지 검증은 Phase E에서 수행한다.

Phase E: 복구 현장/외근·전환 중단·시설별 출력·부상·사망·우선순위·전력 경고·일시정지·저장 왕복 투영 검증 완료. WebGL 미지원 UI 테스트 추가. 전체 61개 테스트 통과, 이후 관련 20개와 타입/빌드 통과. 브라우저에서 관리/내부/도시 공유 시간과 정지 저장 재접속을 확인했다. 최종 리소스·이동·성능 확인은 Phase F 기록을 따른다.
