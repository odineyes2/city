# 1단계 개선 — 기반 시스템 안정화

## 기존 구현과의 차이

| 영역 | v1                                   | v2                                       |
| ---- | ------------------------------------ | ---------------------------------------- |
| 시간 | UI 타이머 1회=1시간, 부재도 3초 배율 | 실제 경과, 독립 배율·잔여 시간·정지 보존 |
| 경제 | 순변화만, 전력 재고 검사             | 생산/소비/손실 원장, 전력 예산·부분 공급 |
| 건물 | 비용·위험 차이, 용도 유사            | 유형·구조·난이도·적합성·제한·활성 효과   |
| 전환 | 즉시 무료                            | 자재 선납, 기존 운영 중단 후 인력 작업   |
| 작업 | 복구 우선 고정, 이전 배정 없음       | 분야 우선순위·건강 효율·배정 유지        |
| 저장 | 기본 검사                            | v1 이관·백업, 참조/상태 검증·재개 기록   |
| 행동 | 중복 실행·조건 피드백 부족           | 요청 ID 멱등 처리·실행 불가 사유 표시    |

## 모듈 경계와 수치

- `config.ts`: TIME, ECONOMY, WORK, LIFE, ACTIONS. 기본 온라인 3초, 부재 5분/1시간, 상한 12시간, 생산·소비·작업·비용을 조정한다.
- `model.ts`: v2 상태·시계·우선순위·배정·건물 특성·복구/전환 project.
- `data.ts`: 기존 초기 주민·20개 건물·시설 6종.
- `buildings.ts`: 구조물 프로필·적합성·설치 제한·효과와 작업 견적.
- `economy.ts`: 1시간의 순수 배정·생산·소비·전력 원장. UI 예측과 실제 틱이 공유한다.
- `engine.ts`: 기존 개척·전투·외교·계승 명령 유지. 원장 반영 후 사건·완료 처리.
- `time.ts`: 실제 경과 → 게임 시간. UI와 독립적인 순수 함수.
- `save.ts`: 검증·v1 이관·부재 계산. 브라우저 I/O 없음.
- `storage.ts`: 기존 슬롯·재개 기록·소비 시각과 원본 보존.
- `Management.tsx`, `App.tsx`: 기존 지도·탭을 유지하며 원장·우선순위·건물 보고·사유를 연결한다.

## 경제 처리 순서

1. 중상·저건강 주민을 제외하고 우선순위 → 복구/시설/쉘터 → 가능한 기존 배정 순으로 작업한다. 한 사람은 한 작업만 맡는다.
2. 역할 적합성을 유지한다. 복구는 비경비 인력을 사용하되 복구 순위가 경비보다 높으면 경비도 투입할 수 있다. 높은 방어 우선순위의 부족 인력은 다른 역할에서 보충한다.
3. 쉘터 생산을 계산하고 재고 + 기본 자재 회수로 유지비를 배분한다. 시설 자재 생산으로 자기 유지비를 같은 시간에 순환 충당하지 않는다. 미납 시 생산 보정은 최소 50%다.
4. 발전량 + 전력 재고에서 생활 전력을 먼저 지급한다. 시설 분야 순위로 공급하고 동률은 건물 ID 순이다. 부분 공급 보정은 `0.35 + 0.65 × 공급 비율`이다.
5. 생산은 `기본량 × 숙련 × 건강/부상 효율 × 적합성 × 전력 보정 × 유지 보정`. 회수 정책은 쉘터·작업장 모두에 적용한다.
6. 실제 지급 가능한 생활 소비와 필요량을 구분하고 저장 초과를 계산한다. 틱은 같은 결과를 반영한다.
7. 욕구/회복, 작업 완료, 이주·계약 정산을 처리한다. 구조 변화 후 배정을 갱신해 중단 시설의 유령 작업이 저장되지 않는다.

방위 초소는 배정 인원·효율·적합성으로 전투 보너스를 보정한다. 폐병원은 작은 부상 회복 효과만 있고 별도 의료 시스템은 없다.

## 행동 비용·시간

탐색·협상·전투는 즉시 해결하는 지도자 결정이다. 탐색은 전력, 협상은 식량/식수, 전투는 승패와 무관하게 출정 보급을 사용한다. 조건 실패는 원본 상태를 반환한다. 실제 회수량·저장 초과 손실을 기록한다.

최초 용도 지정은 확보 상태에서 무료·즉시 처리한다. 복구와 운영 시설 전환은 한 번 선납하고 최대 2명의 인력으로 진행한다. 인력이 없으면 추가 차감 없이 대기한다. 전환 중에는 해당 건물을 가동 건물로 세지 않아 수용/저장 효과도 중단된다. 역할·정책·우선순위 변경은 무료·즉시다. 최고 관계 선물과 교역품 공간 부족은 거부한다.

## 저장·시간 정책

- v1은 주민·자원·소유권·관계·계약·작위·진행률을 보존한다. 기존 제한 시설은 호환 예외로 유지한다. 기존 복구는 작업량 100으로 재구성한다. 속도를 알 수 없으므로 정지로 이관한다.
- v2는 속도·분수 시간·우선순위·배정·작업을 저장한다. 신규 캠페인 UUID는 UI 경계에서 제공하며 게임 난수 시드와 구별한다.
- 온라인은 가속도를 곱해 누적하고, 큰 정지 복귀는 한 번에 24시간으로 제한한다. 오프라인은 진행/정지만 확인해 독립 배율과 12시간 상한을 적용한다.
- 캠페인별 부재 소비 시각과 마지막 원본의 재개 결과를 기록한다. 동일 원본은 재개 결과를 재사용하며 과거 시간·분수 시간을 재지급하지 않는다. 오래된 수동 저장은 되돌리기용이며 이후 접속 중 시간을 부재로 지급하지 않는다.
- 쓰기 실패·손상된 재개 기록은 복원을 적용하지 않는다. 순수 `deserialize`에는 외부 이력이 없지만 실제 UI는 항상 `resumeGame`을 사용한다. 다른 브라우저나 삭제된 저장소의 이력은 알 수 없다.
- 이관 원본·손상 슬롯을 별도 보존한다. 자동/수동 모두 실패하면 자동 덮어쓰기를 중단한다. 내보내기는 현재 메모리 상태를 파일로 만든다.
- 자동 저장은 2초 주기·숨김/종료 이벤트·명령 직후에 한다. 정지도 즉시 저장한다. 강제 종료 시 마지막 저장 이후 진행은 보장할 수 없다.
- 최근 256개 요청 ID를 보존하고 UI의 300ms 이내 동일 행동 입력도 차단한다. 다른 ID로 의도적으로 반복하는 선물·교역은 별도 결정이다.

## 검증과 알려진 한계

기존 엔진 14개를 유지하고 시간 정책에 맞게 오프라인 테스트의 속도·시간 상수를 수정했다. 1단계 24개와 운영 서버 3개를 포함해 총 41개다. 재고 0에서 발전으로 가동하는 경우, 부분 전력 배분, 인력 경쟁, 전환 중 저장, v1 작위·원본 백업, 잘못된 참조 거부와 남작 획득을 검사한다. 최종 명령은 `npm test`, `npm run build`이며 빌드에 타입 검사를 포함한다.

화면 자동 조작·스크린샷은 생략한다. 수동으로 정지 후 재접속, 진행 저장 후 현실 5분 뒤 재접속, 식량 우선순위, 전환 비용·생산 중단·완공, v1 JSON 가져오기를 확인할 수 있다.

인력·전력 배분은 공동체 규칙이며 송전망·물리적 이동은 계산하지 않는다. 동률 복구 현장은 건물 ID 순이다. 부족 예상은 현 상태 유지 가정이며 이주·작업 완료·계약 비용 이후 달라진다. 다중 탭 병합·서버 동기화·손상된 재개 기록 전용 복구 화면은 없다. 다음 단계는 플레이 수치 조정, 복구 대기열 순서, 시설 일시 정지, 다중 탭 보호다. NPC 전쟁·정치·관계망·추가 전투 모드는 이번 범위 밖이다.
