# 잔해의 도시 · ASHEN CITY v3.2 (0.3.2)

기후 아포칼립스 이후의 도시에서 쉘터를 운영하고, 건물을 개척하고, 주변 귀족과 교섭해 남작으로 인정받는 브라우저 싱글플레이 전략 프로토타입입니다. 서버나 API 키 없이 로컬에서 실행합니다.

## v3.2 도시와 오버레이

3D 도시는 계속 마운트된 기본 배경입니다. **건물 내부**는 90% 크기의 라이트박스, **관리**는 94% 크기의 공동체 운영실로 열립니다. 한 번에 하나의 오버레이만 표시하며, X·Escape·도시 복귀 버튼으로 닫습니다. 관리에서 건물로 돌아가면 같은 건물과 내부 카메라를 복원합니다. 관리 탭·입력·스크롤도 유지합니다. 작은 화면에서는 전체 화면 오버레이를 사용합니다.

오버레이에서는 도시 입력과 렌더링만 중단하고 게임 시간은 기존 설정대로 진행합니다. 닫으면 이전 도시 카메라 그대로 현재 게임 상태를 표시합니다. 포커스를 내부로 제한하고 닫을 때 복원합니다. 브라우저 뒤로 가기도 오버레이를 닫으며 별도 페이지로 이동하지 않습니다. 새로고침 시 UI 세션은 초기화하고 게임 저장 버전은 **2** 그대로 유지합니다.

카메라 이벤트 리스너 재연결 문제를 수정했습니다. 마우스 이동·회전·줌을 실제 이벤트로 검증했고, 세 가지 오버레이 경로를 각각 20회 반복했습니다. 복구 진행, 전력 배분과 실제 출력, 주민의 배정·부상·식량/식수 부족을 시각화에 연결했습니다. 단위 테스트 71개와 브라우저 검사 9개를 통과했습니다. 소프트웨어 렌더링 환경의 실측은 도시 10 FPS·내부 28 FPS로, 30 FPS 목표 달성은 미확인입니다. 원인·측정 조건·변경 파일·제한은 [v3.2 개발 기록](docs/V3_2_DEVELOPMENT.md)에 있습니다.

## v3 공간 화면

기본 화면은 **3D 도시**입니다. 20개 기존 건물과 도로·교차로·보도·차량·잔해·식생·고가 구조물, 유형별 외벽·창문·파손·옥상 설비를 절차적 메시로 표현합니다. 클릭한 건물에서 기존 규칙의 탐색·점령·복구 명령을 실행하고, 확보한 건물은 **내부 보기**로 들어갑니다.

- 도시: 왼쪽 드래그 이동, 오른쪽 드래그 회전, 휠 줌. 하단 버튼 또는 방향키, `Q/E` 회전, `+/-` 줌, `F`로 선택 건물에 집중합니다. 6px 이상 드래그하면 건물 클릭을 무시합니다. 건물 목록에서도 20개 구역을 선택할 수 있습니다.
- 내부: 대표 쉘터 5개 층과 수경재배·정수·정비·발전·생활·경계·회복·미복구 공간을 관찰합니다. 드래그/방향키 이동, 휠/± 줌, `F` 전체 보기, 층·방·주민 목록을 지원합니다.
- 주민 10명은 실제 ID·작업 배정·건강에 연결됩니다. 역할/작업이 바뀌면 계단 경로를 따라 새 위치로 이동합니다. 경계·운반·재배·기계 조작·복구·휴식·부상 자세를 구분합니다. 일시정지는 작업과 이동도 멈추며 카메라는 계속 조작할 수 있습니다.
- **관리**에서 기존 v2의 모든 생산·주민·정책·외교·저장·JSON 기능을 이용합니다. 화면 전환은 시간과 게임 상태를 초기화하지 않습니다. 관리에서 내부로 돌아오면 마지막 선택 건물을 사용합니다.
- WebGL 초기화가 불가능하면 **관리 화면에서 계속**을 누르세요. 경제는 애니메이션 도착을 기다리지 않습니다. 기존 저장 버전은 **2** 그대로이며 렌더러 위치/프레임은 저장하지 않습니다.

그래픽 라이브러리는 Three.js / React Three Fiber / Drei / PixiJS(MIT)입니다. 건축·설비·주민은 프로젝트 코드로 직접 그렸으며 외부 게임 이미지·모델을 사용하지 않습니다. 상세 단계·변경 파일·검증·제한은 [v3 개발 기록](docs/V3_DEVELOPMENT.md)을 참고하세요.

## 1단계 개선 (v0.2)

온라인/오프라인 시간·속도·잔여 시간과 v2 저장을 분리했습니다. 자원 바 아래 **시간당 원장**에서 생산·생활/시설 소비·총 필요량·실제 재고 변화·저장 초과·부족 예상을 확인합니다. 주민 탭에서는 식량·식수·전력·자재·복구·경비 우선순위를 정합니다.

20개 건물에 구조·유형·적합성·제한·활성 효과를 추가했습니다. 운영 시설 전환은 자재를 한 번 내고 복구 인력이 작업하며, 그동안 기존 효과가 중단됩니다. 비용·기준 소요 시간·인력 대기와 실행 불가 사유를 표시합니다. 시간·경제·행동 수치는 `src/config.ts`에서 조정합니다.

**v1 저장은 주민·자원·영토·관계·작위·계약·복구 진행을 보존해 v2로 이관합니다.** 과거 속도 정보가 없으므로 안전하게 정지로 시작하며, 기존 비적합 시설도 강제 철거하지 않습니다. 기존 슬롯 이름과 JSON 기능은 유지합니다. 원본은 `ashen-city-v1-backup-*`, 손상 슬롯은 `*-recovery`에 보관합니다. 둘 다 복구 불가 시 원본 자동 덮어쓰기를 중단합니다.

진행 중 종료는 현실 **5분당 게임 1시간, 상한 12시간**이며 이전 속도를 복원합니다. 정지·계승·종료 상태에서는 부재 계산을 하지 않습니다. 같은 원본의 재개 결과와 소비 시각을 기록해 중복 시간 지급을 막습니다. 저장 실패는 화면에 표시하며 내보내기로 현재 진행을 보존할 수 있습니다.

신규 모듈: `config.ts`, `buildings.ts`, `economy.ts`, `time.ts`, `save.ts`, `storage.ts`, `Management.tsx`. 기존 `engine.ts`, `data.ts`, `model.ts`, `App.tsx`를 재사용·연결합니다. 상세 설계·검증·한계는 [1단계 개발 기록](docs/STAGE_ONE.md)에 있습니다.

수동 확인: 정지 저장 후 재접속, 진행 저장 후 현실 5분 뒤 재접속, 식량 우선순위 변경, 시설 전환의 자재 차감·생산 중단·완공, v1 JSON 가져오기. v0.2 단계에서는 화면 자동 검증을 수행하지 않았습니다. v3에서는 주요 흐름과 장면 일부를 실제 브라우저로 검증했습니다. 여러 탭 동시 플레이와 서버 저장 동기화는 지원하지 않습니다.

## 실행

Node.js **20.19+ 또는 22.12+**가 필요합니다. 개발 환경에서는 Node.js 26.7.0 / npm 12.0.2를 사용했습니다.

```powershell
cd "C:\Users\Simon Lomebrote\Projects\apocalypse-city"
npm ci
npm run dev
```

브라우저에서 터미널에 표시되는 주소(기본 `http://127.0.0.1:5173`)를 여세요. 포트가 사용 중이면 Vite가 다음 포트를 사용합니다. 처음에는 일시정지 상태입니다. 상단 **1시간** 버튼 또는 **1·2·4배속**으로 진행합니다. 플레이 가이드와 저장/불러오기는 관리 화면에 있습니다.

```powershell
npm test            # 엔진·투영·경로·오버레이·WebGL 대체·서버 71개 테스트
npm run typecheck   # TypeScript 검사
npm run build       # 타입 검사 + 프로덕션 빌드 → dist/
npm run preview     # 빌드 결과 로컬 서비스, 기본 4173 포트
```

명시적으로 브라우저 자동 검사를 실행하려면 다음을 사용합니다. 별도 브라우저 프로필에서 실행하며 전체 화면 캡처는 하지 않습니다. 성능 수치는 장치와 그래픽 백엔드에 따라 달라집니다.

```powershell
npx playwright install chromium
npm run build -- --outDir .release-stage
npm run test:browser # 마우스·오버레이·피드백·반복·모바일·WebGL 대체·성능
npm run test:camera # 실제 마우스 조작만 검사
```

`dist/index.html`을 파일로 직접 열지 말고 HTTP 서버로 서비스하세요.

## 실제 플레이 경로

안전한 첫 승리 경로입니다. 아래는 실제 명령 처리와 시간 진행만 사용하는 자동 테스트로 검증합니다.

1. **옛 식료품점** 선택 → 보급·양도 협상(식량·식수 각각 12) → **수경 농장** 지정 → 복구 시작 → 5시간 진행.
2. **골목 정비소** 선택 → 보급 협상 → **정수 시설** 지정 → 복구 시작 → 5시간 진행.
3. 두 건물 사이 **미확인 구조물(서부에서 두 번째 열·두 번째 행)** 선택 → 탐색(전력 2). 발견 이름은 **철골 주차장**입니다. 보급 협상 → **주거 구역** 지정 → 복구 시작 → 5시간 진행.
4. 게임 **D02 · 12:00(누적 36시간)**까지 진행하면 이주민 2명이 합류합니다. 운영 건물 4곳(쉘터 포함), 주민 12명, 안정도 60 이상을 달성합니다. 시설 복구 전에 지나간 이주 주기에는 주민이 오지 않습니다.
5. 외교 탭에서 **교각 연맹**에 **보급 전달 4회**(식량 총 60). 관계가 25에서 73으로 오릅니다.
6. 계약 의무를 모두 해제한 채 **남작 인정 요청**. 충성 서약 없이 독립 남작이 됩니다. 다른 귀족이나 의무가 있는 계약도 선택할 수 있습니다.
7. 첫 이정표 이후에도 생산, 확장, 외교를 계속할 수 있습니다.

전투를 경험하려면 초반 확보 단계에서 자동 전투를 선택하세요. 보급 비용이 적지만 승리해도 부상이 발생합니다. 전투 후 기다리면 부상이 회복됩니다. 무리한 연속 출정과 강한 방어 시설은 사망 위험을 높입니다.

## 구조와 구현 순서

기존 `Projects`에는 여러 독립 프로젝트가 있었지만 이 게임의 저장소는 없어 새로운 `apocalypse-city` 앱으로 구성했습니다. 기존 프로젝트 파일은 수정하지 않았습니다.

```text
src/
  model.ts    # 주민·건물·세력·계약·저장 상태, 명령과 결과 타입
  data.ts     # 초기 20개 건물과 10명 주민, 시설 수치와 표시 이름
  engine.ts   # UI와 독립적인 명령 처리, 경제, 틱, 자동 전투, 저장·복원
  App.tsx     # 공유 상태/시간/저장 소유권 + 기존 관리 대시보드
  game/       # GameShell, 읽기 전용 투영, 3D 도시, Pixi 내부, HUD
  management/ # 기존 대시보드 화면 래퍼
  style.css   # 폐허/재건 미감, 반응형 레이아웃
  main.tsx    # React 진입점
tests/
  engine.test.ts
```

구현은 데이터·엔진 → 지도·시설 운영 → 전투·외교·계승·저장 연결 → 핵심 규칙 테스트·빌드 순서로 진행했습니다. 엔진 함수는 입력 상태를 복제해 반환합니다. 같은 시드와 명령 순서는 같은 결과를 냅니다. 브라우저 저장소와 실제 시간 접근은 UI 및 저장 입출력 경계에 모았습니다.

## 테스트 결과

- Vitest: **65개 테스트** (기존 게임 14개 + 1단계 24개 + 운영 서버 3개 + v3 투영/경로/전환/대체 UI 24개). 시간·정지·독립 부재 배율·중복 재개, 자원 원장·전력 배분·건물 적합성·시설 전환·우선순위·부상·v1 이관·손상 거부와 첫 남작 경로를 확인합니다.
- TypeScript 타입 검사 및 Vite 프로덕션 빌드 통과. 빌드 산출물은 `dist/`에 생성됩니다.
- v3 요구에 따라 실제 브라우저에서 주요 흐름·선택·역할 변경·일시정지·저장 재접속·반복 전환을 확인했습니다. 장면 일부만 관찰했고 전체 화면/전체 사이트 캡처는 하지 않았습니다. 도시·주민 10명 내부에서 약 52~57 FPS를 관찰했습니다(공개 도시 첫 표본 52, 로컬 안정 표본 약 57). 전용 Playwright 자동 브라우저 테스트와 장시간 힙 프로파일링은 추가하지 않았습니다.

## 한계와 다음 단계

- 첫 수직 슬라이스입니다. 턴제 레이드, 직접 전술 지휘, 도시 전체 지도, 멀티플레이, 서버 동기화, 복잡한 정치·가문·계승법은 구현하지 않았습니다.
- 주민 관계망, NPC 간 자율 전쟁·영토 확장, 적의 정기 침공, 세금 연체에 따른 작위 박탈은 아직 없습니다. 현재 충돌은 플레이어의 영토 공격과 외교 관계로 표현합니다.
- 운영 시설 전환은 자재 선납과 인력·시간을 요구하며 기존 생산·수용·저장 효과를 중단합니다. 장비는 기존 공용 단계를 유지합니다.
- 부재 계산은 온라인과 독립된 현실 5분당 게임 1시간, 최대 12시간입니다. 일시정지 상태로 닫으면 진행하지 않습니다. 정치·계승 자동 결정 없이 복구/전환과 경제만 처리합니다.
- 자동 저장은 브라우저/주소/포트마다 별개입니다. 브라우저 데이터 삭제나 비공개 모드에서는 보존되지 않을 수 있으므로 JSON 파일을 내보내세요. 여러 탭의 동시 플레이는 지원하지 않습니다.
- 도시는 Three.js 메시, 내부는 PixiJS 도형·인체 리깅, 관리 지도는 SVG입니다. Google Fonts 연결이 없어도 시스템 글꼴로 플레이할 수 있습니다. 외부 게임 API나 유료 서비스는 사용하지 않습니다.
- 다음 우선순위: 건물 유형별 내부 전용 아트 → 도시 메시/그림자 최적화와 저사양 옵션 → 다양한 브라우저·모바일 및 장시간 메모리 검증 → 다중 탭 저장 보호. 정치·전투 확장은 이후 별도 단계입니다.
