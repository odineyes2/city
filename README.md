# 잔해의 도시 · ASHEN CITY

기후 아포칼립스 이후의 도시에서 쉘터를 운영하고, 건물을 개척하고, 주변 귀족과 교섭해 남작으로 인정받는 브라우저 싱글플레이 전략 프로토타입입니다. 서버나 API 키 없이 로컬에서 실행합니다.

## 실행

Node.js **20.19+ 또는 22.12+**가 필요합니다. 개발 환경에서는 Node.js 26.7.0 / npm 12.0.2를 사용했습니다.

```powershell
cd "C:\Users\Simon Lomebrote\Projects\apocalypse-city"
npm install
npm run dev
```

브라우저에서 터미널에 표시되는 주소(기본 `http://127.0.0.1:5173`)를 여세요. 포트가 사용 중이면 Vite가 다음 포트를 사용합니다. 처음에는 일시정지 상태입니다. 상단 **1시간** 버튼 또는 **1·2·4배속**으로 진행합니다. 우측 상단 `?`에 플레이 가이드가 있습니다.

```powershell
npm test            # 핵심 엔진 테스트
npm run typecheck   # TypeScript 검사
npm run build       # 타입 검사 + 프로덕션 빌드 → dist/
npm run preview     # 빌드 결과 로컬 서비스, 기본 4173 포트
```

`dist/index.html`을 파일로 직접 열지 말고 HTTP 서버로 서비스하세요.

## 실제 플레이 경로

안전한 첫 승리 경로입니다. 아래는 실제 명령 처리와 시간 진행만 사용하는 자동 테스트로 검증합니다.

1. **옛 식료품점** 선택 → 보급·양도 협상(식량·식수 각각 12) → **수경 농장** 지정 → 복구 시작 → 5시간 진행.
2. **골목 정비소** 선택 → 보급 협상 → **정수 시설** 지정 → 복구 시작 → 5시간 진행.
3. 두 건물 사이 **미확인 구조물(서부에서 두 번째 열·두 번째 행)** 선택 → 탐색(전력 2). 발견 이름은 **철골 주차장**입니다. 보급 협상 → **주거 구역** 지정 → 복구 시작 → 5시간 진행.
4. 게임 **D02 · 12:00(누적 36시간)**까지 진행하면 이주민 2명이 합류합니다. 운영 건물 4곳(쉘터 포함), 주민 12명, 안정도 60 이상을 달성합니다. 시설 복구 전에 지나간 이주 주기에는 주민이 오지 않습니다.
5. 외교 탭에서 **교각 연맹**에 **보급 전달 4회**(식량 총 60). 관계가 25에서 73으로 오릅니다.
6. 계약 의무를 모두 해제한 채 **남작 인정 요청**. 충성 서약 없이 독립 남작이 됩니다. 다른 귀족이나 의무가 있는 계약도 선택할 수 있습니다.
7. 첫 이정표 이후에도 생산, 확장, 외교를 계속할 수 있습니다.

전투를 경험하려면 초반 확보 단계에서 자동 전투를 선택하세요. 보급 비용이 적지만 승리해도 부상이 발생합니다. 전투 후 기다리면 부상이 회복됩니다. 무리한 연속 출정과 강한 방어 시설은 사망 위험을 높입니다.

## 구조와 구현 순서

기존 `Projects`에는 여러 독립 프로젝트가 있었지만 이 게임의 저장소는 없어 새로운 `apocalypse-city` 앱으로 구성했습니다. 기존 프로젝트 파일은 수정하지 않았습니다.

```text
src/
  model.ts    # 주민·건물·세력·계약·저장 상태, 명령과 결과 타입
  data.ts     # 초기 20개 건물과 10명 주민, 시설 수치와 표시 이름
  engine.ts   # UI와 독립적인 명령 처리, 경제, 틱, 자동 전투, 저장·복원
  App.tsx     # 도시 지도·건물 상세·쉘터·주민·외교·기록·계승 화면
  style.css   # 폐허/재건 미감, 반응형 레이아웃
  main.tsx    # React 진입점
tests/
  engine.test.ts
```

구현은 데이터·엔진 → 지도·시설 운영 → 전투·외교·계승·저장 연결 → 핵심 규칙 테스트·빌드 순서로 진행했습니다. 엔진 함수는 입력 상태를 복제해 반환합니다. 같은 시드와 명령 순서는 같은 결과를 냅니다. 브라우저 저장소와 실제 시간 접근은 UI 및 저장 입출력 경계에 모았습니다.

## 한계와 다음 단계

- 첫 수직 슬라이스입니다. 턴제 레이드, 직접 전술 지휘, 도시 전체 지도, 멀티플레이, 서버 동기화, 복잡한 정치·가문·계승법은 구현하지 않았습니다.
- 주민 관계망, NPC 간 자율 전쟁·영토 확장, 적의 정기 침공, 세금 연체에 따른 작위 박탈은 아직 없습니다. 현재 충돌은 플레이어의 영토 공격과 외교 관계로 표현합니다.
- 시설 용도 변경은 운영 중 무료·즉시 적용합니다. 장비는 개인별 인벤토리 대신 공동체 공용 단계이며, 현장 지도자도 동일 보너스를 받습니다.
- 부재 계산은 현실 3초당 게임 1시간을 그대로 환산하는 단순 안전 모델입니다. 오프라인에는 귀족의 자율 행동이 없으며, 정치·계승을 자동 결정하지 않습니다. 일시정지 상태로 닫아도 재접속 시 부재 계산은 적용됩니다.
- 자동 저장은 브라우저/주소/포트마다 별개입니다. 브라우저 데이터 삭제나 비공개 모드에서는 보존되지 않을 수 있으므로 JSON 파일을 내보내세요. 여러 탭의 동시 플레이는 지원하지 않습니다.
- 지도와 건물은 코드로 만든 SVG/도형입니다. Google Fonts 연결이 없어도 시스템 글꼴로 플레이할 수 있습니다. 외부 게임 API나 유료 서비스는 사용하지 않습니다.
- 다음 우선순위: 실제 플레이로 시간·소비·전투 수치 조정 → 주민/시설 수동 우선순위 → 저장 마이그레이션과 다중 탭 보호 → 귀족의 요구·계약 재교섭과 제한적 적대 행동. 추가 전투 모드는 그 이후에 검토합니다.
